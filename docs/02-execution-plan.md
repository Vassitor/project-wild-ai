# 2D 荒野生存：分阶段执行计划

状态：P0–P7 已完成；下一阶段为 P8 验证、性能与导出。更新：2026-10-15。版本：0.2，包含单机与合作任务。

设计依据：[01-game-design.md](01-game-design.md)。已确定决策：[03-design-decisions.md](03-design-decisions.md)。初始配置：[05-initial-balance.md](05-initial-balance.md)。

工程约束：[04-engineering-guidelines.md](04-engineering-guidelines.md)。已取消 5 件限制，改为空间和负重限制；饮水、体力和网格库存进入首版范围。

联机规则与验收：[06-multiplayer-design.md](06-multiplayer-design.md)。P0 准备会话边界，P3 后双人验证，P6 后四人整合；房主承载世界，局域网 / IP 直连起步。

每个阶段完成后交付可验证结果；后续阶段依赖前一阶段验收。规则与初始配置已确定。单工作区顺序实现，原型使用自制占位素材；此计划不承诺日历工期，P3 后用实测开发速度估算剩余工作量。

## P0：落实已确定规则与工程基线

已完成，实施与验证证据见 [P0 报告](07-p0-implementation.md)：Godot 4.7.2、Compatibility、可移动基地、配置 / 会话 / 身份骨架，34 项自动检查通过并完成图形预览检查。

目标：让开发有可执行的规则，避免边做边反复改底层。

任务：

- 核对并记录本机 Godot 完整版本，目标沿用项目声明的 4.7 系列；落实 Windows 10 / 11 x64 键鼠、Compatibility 和单机 / 合作模式配置。
- 记录已确认的视角、时间、损失规则、7 日、技能持久化、胜利物资处理和五类营养模型。
- 按配置表录入背包 8×6 / 30 L、独立体积、18 / 30 kg 负重、饮水 / 体力及 120 倍游戏时钟。
- 建立主流程状态图、目录约定、稳定配置 ID、存档版本约定。
- 定义库存、动作、身体模拟等模块的职责、接口和依赖；记录注释规范与数据单位。
- 定义本地 / 房主会话、稳定玩家 ID、实体归属、命令 / 结果与网络适配边界，规划共享世界与个人档案。
- 先用占位美术确定移动、碰撞、交互提示和 UI 阅读尺度。

交付：可启动的空壳入口、配置清单、状态转换说明、更新后的决策记录。

验收：能进入基地占位场景；规则与配置来源唯一、无冲突；编辑器完整版本与实际渲染器已记录；单机基线和联机扩展已落实，UI 经会话提交操作。

## P1：网格库存、基地购买与出发准备

已完成，实施与验证证据见 [P1 报告](08-p1-implementation.md)：25 种物品定义、网格拖放 / 旋转 / 拆分 / 合并、装备槽、商店、事务档案和准备 / 撤销 / 占位荒野。98 项自动检查通过，P0 回归 34 项通过；完成仓库与商店实际图形预览检查。

目标：完成永久成长与单局物资的边界。

任务：

- 建立物品重量、体积、占格尺寸、实例、堆叠和容器数据结构。
- 独立实现网格放置、旋转、边界 / 重叠检查、重量 / 体积统计，再接拖放界面。
- 实现拆分 / 合并、跨容器转移及失败回滚，记录坐标、旋转和稳定实例 ID。
- 加入玩家归属、私人 / 公共容器权限、版本校验和请求去重，库存事务可由本地或房主会话调用。
- 建立货币与商店购买流程，含余额不足、容量 / 数量检查。
- 制作准备面板，从仓库装入初始物资，展示网格、重量、体积和限制；不设件数上限。
- 引入任务 ID、永久档案 / 单局档案的基本存档结构。
- 实现出发提交和撤销；先使用占位荒野承接转移。
- 落实不可出售的免费小刀 / 打火石 / 空水壶补给及全归属库存防重复领取规则，避免失败后破产卡死。

交付：可购买、选择、保存并进入占位荒野的版本。

验收：空间和负重允许时，超过 5 件仍可出发；越界、重叠、容量超限时拒绝操作并显示原因；旋转、拆分和转移不改变物资总量；购买扣款一次；取消不丢失物资；出发不复制仓库物品；重开能恢复网格布局与永久数据。

## P2：随机荒野、出生点与探索

已完成，证据见 [P2 报告](09-p2-implementation.md)：128×128 随机地形、独立随机流、连通与出生路径校验、519 个资源点、重试 / 安全模板、TileMapLayer、权威移动 / 相机 / 资源详情及完整世界档案。已验证 100 个固定种子并通过 Godot MCP 运行图形预览。采集耗时、饮水与资源再生随 P3 接入。

目标：随机生成可探索、可生存的地图。

任务：

- 建立有限地图数据模型与分层地形显示。
- 实现种子、生态区、水域、地形连通性与资源分布。
- 实现角色移动、碰撞、相机、交互范围和对象提示。
- 候选出生点验证：通行、可离开、附近资源、食物与饮水路径可达；必要的取水 / 净化手段可获得。
- 设置有限重试与安全模板回退；生成成功后才正式提交本局。
- 保存地图版本、资源稳定 ID 和世界变更。
- 世界支持多角色状态，个人输入 / 相机与共享世界分离；准备地图快照与实体生成记录接口。

交付：能够输入种子、生成地图、随机安全投放并移动的版本。

验收：在固定引擎与生成器版本下相同种子重现初始地图；抽样多个种子无水中出生 / 困岛；生成失败有明确回退；资源消耗后读档不重新出现。

## P3：完整小循环原型

已完成，见 [P3 报告](12-p3-implementation.md)：身体 / 时钟、采集 / 伐木、饮食 / 饮水 / 煮水、营地 / 篝火 / 烤根茎、休息 / 睡眠、运行档案和胜负 / 返航闭环。默认规则自动策略在 5 个种子上累计 168 小时获胜，另有死亡 / 取消 / 写盘失败 / 满包满仓 / 结算去重验证。正常速度人工平衡试玩留待后续；扩大内容前先按计划验证双人网络边界。

目标：尽早玩完一局，验证核心体验；采用最终 7 日目标并提供仅用于调试的加速。

任务：

- 实现统一游戏时钟、单机背包 / 制作选择暂停和动作耗时；暂停是会话策略，合作个人面板不暂停。
- 实现血量、基础伤害、食物、简单恢复和背包管理。
- 接入五类营养字段与基础消耗 / 进食；复杂缺乏症延后到 P4。
- 实现水分消耗、取水、饮用与基础煮水；正确计算水容器内容重量。
- 实现基础体力、冲刺 / 劳动消耗、休息恢复与负重影响；具体严重状态延后到 P4。
- 实现采摘、伐木、取火、一种料理和一个简易营地。
- 实现基础休息 / 睡眠；跳时必须推进生存损耗、火源和食物状态。
- 实现到达目标胜利、血量归零失败、奖励与返航。
- 完成出发、运行中、结算三个关键存档点。

交付：基地购买 → 网格装载 → 随机投放 → 获取食物、水与木材 → 管理体力并建营地休息 → 7 日结算 → 基地的可玩版本。

验收：可以正常走完成功与失败两条路线；菜单暂停不消耗时间且不能免费生产；饮水有效、劳动消耗体力、休息恢复体力；零体力仍可缓慢移动并获得恢复机会；结算奖励只发一次；胜利随身物资返仓；失败丢失本局物资、保留永久进度；存档恢复时间、身体、库存和营地状态。

阶段检查：评估探索与等待是否有趣，网格和负重是否带来选择，饮水与体力是否制造合理压力，睡眠是否压缩重复等待。若核心循环无聊，先调整，不立即扩大内容数量。

## P3.5：早期双人联机验证

已完成，见 [P3.5 报告](13-p35-implementation.md)：独立双人入口、房主权威与 ENet、私人网格库存 / 独立公共箱、动作 / 占地锁、断线留存与原成员重连。80 项领域检查、22 项实际 UI 检查；正常网络 61 项与 100 ms / 1% 应用报文故障 63 项通过，均由真实双进程运行。合作验证档案 / 物资与永久基地隔离，P6.5 的完整四人、睡眠 / 尸体 / 逐人结算未提前实现。

目标：扩大玩法内容前验证共享世界、权限和并发事务。

任务：

- 用 Godot 高层联机 API / ENet 实现房主与客户端、本机双进程及局域网 / IP 连接。
- 房主发送地图 / 实体快照，维护身份与运行状态，支持移动输入、位置同步和插值。
- 接入房主校验的拾取、库存转移、公共箱、建筑占地 / 材料预留和提交。
- 实现基础断线留存 / 原成员重连、请求去重和错误反馈；合作个人菜单继续推进世界。
- 验证抢同一物品、同格建造、公共箱并发、恢复角色不重复。

交付：两人能在同一随机荒野移动、采集、共享物资、建营地并重连的验证版本。

验收：共享权威状态一致，没有物资 / 材料 / 角色复制；个人菜单不暂停另一人；100 ms 模拟往返延迟、1% 丢包下记录交互与恢复结果。本阶段不等于完整四人联机完成。

## P4：完整身体状态、营养、饮水、体力与疾病

已完成，见 [P4 报告](14-p4-implementation.md)：营养 / 脱水迟滞、污染疾病、出血 / 肠胃不适 / 衰弱、治疗、护甲、身体详情和兼容存档。98 项领域、16 项 UI、正常 43 / 故障 44 项真实双进程检查；回归 571 项通过，5 种子在新规则下完成 168 小时。物理伤害接口已验证，动物攻击交互仍待 P6；正常速度人工平衡试玩留待后续。

目标：让饮食和疗养成为可理解的策略。

任务：

- 明确五类营养的范围、消耗、食物补给、消化和不足累计。
- 加入健康值、恢复系数、状态效果与护甲规则。
- 完善缺水、脱水、不洁饮水、体力恢复修正和负重惩罚；各数值来源可追踪。
- 实现首批疾病 / 伤病：出血、肠胃不适、衰弱。
- 实现食品卫生、药品 / 绷带、疗养及疾病恢复条件。
- 制作身体详情面板与症状提示，解释行动效率下降来源。
- 实现配置表定义的首轮病程 / 消耗 / 恢复；试玩变更记录数值版本，避免首日随机暴毙或完全没有压力。
- 合作身体状态和随机疾病由房主模拟，每人状态独立；新增规则经过单机与双人验证。

交付：可通过进食、饮水、治疗、休息调整营养、水分、体力和健康，并观察疾病发展与恢复。

验收：不同食谱产生不同状态轨迹；营养不足和缺水按规则累计风险；水分 / 健康影响体力恢复；负重对行动的影响有反馈；护甲只减免指定伤害；治疗条件明确；普通实时推进和睡眠跳时使用一致规则，跳时不跳过脱水或疾病。

## P5：技能、捕鱼、陷阱与营地升级

已完成，见 [P5 报告](15-p5-implementation.md)：九分支 / 27 节点、有效实践与基地学习、技能持久化、捕鱼 / 鱼点再生、小型 / 大型陷阱、营地 2 / 3、料理台和新增配方。220 项领域、33 项 UI、正常 68 / 故障 70 项真实双进程检查，共 391 项通过；回归 772 项通过。陷阱消耗实际静态兔 / 野猪实体，AI、动态足迹、武器攻击与狩猎掉肉加成待 P6；合作技能保存于验证房间，跨设备个人基地成长交付仍待 P6.5。

目标：形成多条生存路线并接入永久成长。

任务：

- 实现分支经验、技能点、技能前置条件和节点解锁。
- 实现基地货币学习与实践学习，两者指向同一节点。
- 持久化有效实践获得的技能经验和点数；失败保留永久技能、经验和未使用点数。
- 扩展捕鱼、制造 / 放置 / 收取陷阱、营地升级、料理配方和医疗技能。
- 检查工具、技能、资源、环境和空间要求，显示不满足的原因。
- 让陷阱、燃料和恢复在离开视野、睡眠、存读档时一致运行。
- 技能和经验归执行者，公共设施仍检查使用者技能；材料和延迟产出由房主统一提交并同步。

交付：捕鱼、采集、陷阱等可替代或互补的食物路线；技能能明确改变可用互动与效率。

验收：未解锁高级技能不能进行对应互动；基础生存无需预先购买技能；无产出刷动作不能无限获点；基地已学习的节点不会重复扣费；营地升级收益可观察。

## P6：动物、狩猎与战斗

已完成，见 [P6 报告](16-p6-implementation.md)：兔 / 野猪 / 狼动态 AI、刀 / 斧 / 弓箭、冷却 / 体力 / 耐久、实际护甲伤害与出血、唯一死亡掉落、动态足迹、视野外有界刷新、出生保护、陷阱共用实际动物、睡眠风险与攻击中断。119 项领域、15 项 UI、正常 47 / 故障 48 项真实网络检查，共 229 项通过；回归 1163 项通过，五种子适应风险的默认资金策略走满 168 小时。原生动物示意与简易动效可玩，美术细化 / 平衡仍待整合；本阶段实现动物人数倍率，完整资源倍率、个人成长交付与四人生命周期待 P6.5。

目标：补齐用户要求的狩猎与外部风险。

任务：

- 按已定的兔 / 野猪 / 狼与近战 / 弓箭方案，实现动物游走、警觉、逃跑 / 攻击与死亡。
- 实现追踪或接近、攻击反馈、护甲、装备耐久和受伤。
- 加入动物掉落、肉类料理、陷阱与动物的关系。
- 控制刷新、栖息地、数量上限和危险区；防止安全出生点立即受致命攻击。
- 保存动物与陷阱关键状态；避免同一猎物重复掉落。
- 合作动物 AI、伤害、死亡和掉落由房主判定，无友方伤害；按出发人数配置危险倍率。

交付：包含风险和收益的狩猎循环，可与捕鱼 / 采集路线比较。

验收：可以追踪 / 接近、猎杀、获得物资并料理；动物不穿墙、不无限追击；物资只结算一次；护甲有明确效果；睡眠受袭可合理打断。

## P7：内容整合、经济与可用性

已完成，见 [P7 报告](18-p7-implementation.md)：共用 F1 手册、出发检查、倒计时、逐人奖励 / 返航明细和旧档兼容；三条食物路线控制实验与三套采购验证支持暂时保留当前价格、培训和奖励。既有内容已核对入口；实际四进程合作与单机七日回归独立验证。控制实验不代替 P8 人工七日、跨设备和性能 / 导出验收。

目标：整合单机与合作为可重复游玩的完整首版。

任务：

- 补齐商店、装备、食物、疾病、配方、技能与建筑的首批内容。
- 根据试玩调整货币奖励、培训成本、携带选择和物资稀缺度。
- 落实胜利随身物资返仓和营地留存物资不带回，以持久化待领取区处理满仓，以免费补给处理零货币重新出发。
- 加入出发引导、交互原因、倒计时、任务摘要和结果界面。
- 完成档案持久化、读档兼容性、自动存档与异常恢复。
- 检查长动作跨目标时间、同刻死亡与胜利、场景切换重入等边界。
- 检查多人公共物资、尸体 / 队友返仓、个人奖励、难度倍率，以及不同模式的暂停 / 睡眠规则。

交付：用户要求的全部首版机制已可串联试玩的候选版本。

验收：每项需求有可操作入口与反馈；至少比较采集、捕鱼、狩猎三条食物路线；没有必须依赖一种永久技能才能开局的死锁；胜利返航与失败返航符合约定；不重复发奖。

## P8：验证、性能与导出

已交付本机自动验证与 Windows x64 0.2.0-rc1 候选包，见 [P8 报告](19-p8-implementation.md)。百种子、五种子默认速度自动生存、四进程 150 ms / 5% 应用报文故障和发布 EXE 冒烟 / 双进程结算已验证。性能仍有超标，参考 8 GB 配置、完整发布包人工七日与跨设备 LAN 未验收；本阶段保持「候选交付、验收未全通过」，下一步优先处理保存与四人房主帧时间。

目标：交付可运行的 Windows 版本和使用说明。

任务：

- 执行地图校验、网格旋转 / 越界 / 重叠、堆叠重量 / 体积、跨容器回滚、购买边界、技能条件、结算幂等与存档恢复检查。
- 比较普通推进与睡眠跳时的身体 / 世界状态；不要求所有随机事件逐帧完全相同，但规则必须一致。
- 对 100 个固定种子自动验证出生与连通性，至少 5 个种子正常速度完成任务，并比较不同装备组合与三条食物路线。
- 检查大量地形、建筑、动物和存档时的帧率 / 加载时间；根据实际瓶颈优化。
- 检查中文显示、缩放、输入、音量与反馈；完善最小可用教程。
- 核对素材许可、导出模板和目标平台，在编辑器外验证导出包。
- 检查模块职责与依赖、共享配置是否被误改、关键接口 / 算法 / 单位注释是否完整。
- 完成双人和四人测试，模拟往返延迟 150 ms / 丢包 5%，覆盖重连、个人菜单、睡眠、房主退出、跨端结算重发。

交付：可运行游戏包、操作说明、已知问题与版本记录。

验收：编辑器外可启动、单机完成一局、建立合作房间并完成逐人结算 / 重连 / 存档；参考四核 CPU、8 GB RAM、OpenGL 3.3 显卡下，1080p 目标 60 FPS、生成 ≤3 秒、存档主线程阻塞 ≤100 ms，分别记录单机和四人房主的实测结果。

## 执行优先级与依赖

```text
P0 规则 / 版本 / 会话与模块契约
 → P1 网格库存 / 基地 / 档案
 → P2 地图 / 探索
 → P3 完整小循环与早期试玩
 → P3.5 双人联机验证
 → P4 身体 / 饮水 / 体力 / 疾病
 → P5 技能 / 活动扩展
 → P6 动物 / 狩猎
 → P6.5 完整 2–4 人合作
 → P7 整合 / 平衡
 → P8 验证 / 导出
```

P3 是优先交付的单机小循环，P3.5 在扩大内容前验证联机边界。美术、声音和更多配方在系统稳定后补充；网络只在适配层实现，单机与合作共用领域规则。
