## 合作与发布验证边界

四个真实 Godot 进程，仅绑定回环随机 UDP 端口，验证提交个人物资 / 加载屏障、公开物资并发、赠送、个人菜单、睡眠中断、离线死亡 / 尸体、原成员重连、成长与逐人结算重发、房主进程恢复。

故障层使用单向 75 ms 延迟、每 20 个应用报文丢弃 1 个，配置往返为 150 ms，另保留定向丢失请求 / 结果检查。它运行在真实 ENet 上，**不是 OS 层 UDP 丢包整形**；有限报文数的实际比例以结果 JSON 为准。房主恢复前后的结果分别留证。

发布 EXE 的两个真实进程使用相同延迟 / 丢弃配置，经过实际完整合作 UI / 会话提交，验证原角色断线重连、个人收据写盘与双方成功结算。普通测试场景不进 PCK。官方发布模板禁用外部脚本覆盖，因此候选包包含受 `candidate_qa` 特征和显式 `--qa-probe` 控制的诊断入口；在正式身份初始化之前启用，只能写 EXE 旁 `qa/p8-export-*`。发给用户的 ZIP 仅列入交付文件，排除 QA 输出。

所有检查使用工作区随机隔离身份 / 世界或 EXE 旁 QA 隔离目录。正式基地文件只比较大小和时间元数据，未作为测试输入。旧文件 25902 / 228157 字节和时间戳保持原值，且未新增正式提交日志，见 `evidence/p8-formal-files.json`。
