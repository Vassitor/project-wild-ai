## 1. 用户确认的规则

| ID | 项目 | 确认规则 |
| --- | --- | --- |
| N01 | 模式 / 人数 | 2–4 人合作，无 PvP；个人物资与共享营地并存 |
| N02 | 连接 | 房主兼玩家，局域网 / IP 直连起步；网络层预留后续平台邀请或中继 |
| N03 | 暂停 / 睡眠 | 个人菜单不暂停；全体在线存活者同意后跳时；遇威胁中断 |
| N04 | 死亡 / 胜负 | 死亡观战，无复活；尸体物资队友可取；到期存活者获奖，全员死亡失败 |
| N05 | 存档 / 重连 | 房主保存共享世界，各人保存个人基地 / 成长；断线角色原地留存，可重连；房主离开保存并结束房间 |
| N06 | 中途加入 | 只允许原队员重连，新玩家等下一局 |
| N07 | 物资 / 技能 | 背包私人、营地箱公开、可主动赠送；技能经验独立，谁执行谁获经验 |
| N08 | 难度 / 奖励 | 资源与危险按出发人数温和增加；存活者独立获得基础奖励与个人活动奖励 |

## 2. 流程与模式差异

各人在个人基地准备 → 房主建房 → 队员加入 / 提交装备和技能 → 全员准备 → 锁定名单与出发人数 → 房主生成并发送世界快照 → 全员加载完成后统一投放 → 共享 168 小时倒计时 → 逐人结算。

每人背包、空间 / 体积 / 重量和技能独立校验，不因人数增加个人容量。投放在同一安全出生区的不同可通行格；身体仅初次投放重置，恢复旧任务 / 重连不重新初始化。

| 行为 | 单机 | 合作 |
| --- | --- | --- |
| 背包 / 制作菜单 | 暂停模拟，提交动作后恢复 | 本地面板，世界和身体继续 |
| Esc / 失去焦点 | 全局暂停 | 本地菜单，停止输入但角色仍受世界影响 |
| 睡眠 | 自选 1 / 2 / 4 / 8 小时 | 全体在线存活者同意同一时长 |
| 自己死亡 | 本局失败，物资清除 | 转观战，物资入尸体，队友继续 |
| 新玩家加入 | 不适用 | 任务开始后禁止，仅原队员重连 |
| 结束 | 本人到期存活 / 死亡 | 到期存活者胜利，或全体角色死亡失败 |

睡眠提案 30 现实秒内未全员同意则取消；跳时不能另行劳动或转移物资。受攻击、出血、任一存活角色血量 ≤20 / 水分 ≤20 时中断，包括断线留存角色。世界、营养、水分、病程、腐坏、燃料、陷阱都走相同模拟路径。

断线不等于死亡，角色仍消耗营养 / 水分并可能受伤。断线取消未完成动作、释放未耗材料，不退已用时间 / 体力 / 鱼饵 / 箭矢；重连先绑定原身份、加载快照再恢复输入，不创建第二个角色或带入新物资。

房主主动退出先存世界与成员状态再关闭房间，不做房主迁移；异常掉线时客户端停止接受新世界操作，保留个人提交记录，等待原房主恢复最后完整存档后核对事件。掉线不触发胜利、物资自动返还或身体重置。

## 3. 权限与共享

- 私人背包 / 装备仅本人操作，详细库存只同步本人；公共箱和地面资源所有队员可操作。
- 赠送为明确转移事务，目标玩家确认接收且容量允许。不能任意将物品推入对方背包。
- 死亡先中断动作并释放未耗材料，再原子转移随身物资到尸体；队友拿走后成为队友当前持有，不在死者返仓时复制。
- 技能 / 经验 / 点数独立，执行者得到有效行动经验；公共设施使用仍检查使用者自己的技能，不借队友节点绕过门槛。
- 建造可选择个人与公共箱材料，房主集中预留数量和占地，取消释放；同时取料不能重复消费。
- 无 PvP，友方攻击不伤害队员；外部危险仍正常作用。

## 4. 权威模拟与模块边界

单机由本地会话执行，合作由房主执行同一领域规则。客户端提交输入和意图，不直接决定库存变化、建造、伤害、产出、经验或奖励。

房主生成世界、推进时钟，处理动物 / 陷阱 / 身体 / 资源 / 随机结果并结算；客户端显示状态，不独立抽疾病或掉落随机数。

命令含 `session_id`、`run_id`、`request_id`、目标 ID、预期状态版本和参数。连接层从实际消息来源绑定稳定 `player_id`，不信任消息任意声明的操作者；领域代码不依赖临时 peer ID。

共享库存校验权限、距离、数量、空间、体积、重量和状态版本；房主按事务顺序提交，旧版本拒绝后刷新。建筑预留占地，掉落与死亡有唯一事件 ID，同请求重发不重复扣款 / 扣材料 / 发奖励。

领域校验仍同步返回结果；会话 / 网络请求可异步完成，UI 展示等待、成功或失败原因，不提前认定提交成功。网络适配层不侵入网格、配方、营养或技能公式。

## 5. 网络技术与同步

采用 Godot 高层联机 API / ENet，UDP 7000 默认端口可配置，支持本机双进程、局域网 / IP。公网直连需要实际网络可达，不等于免配置好友邀请；中继、平台邀请、专用服务器、房主迁移不纳入第一联机版本。

P6.5 网络协议升级为 3：有界压缩的可靠世界快照 / 初始地图、独立可靠结果 / 结束收据、不可靠有序位置 / 输入分别传输，避免大快照顺序积压。完整合作握手同时检查玩法 / 内容摘要，原双人入口也检查协议版本。

初始输入 20 Hz、位置快照 10 Hz，客户端插值；完整联机阶段加入本地移动预测与房主纠正。库存 / 建造 / 技能 / 伤害 / 死亡 / 结算使用可靠消息，位置等高频更新与事务分流。

实体生成 / 销毁与同步由独立网络适配层负责，RPC 节点路径与命名一致。消息使用稳定 ID 和可序列化基础数据，不传场景节点 / Resource / 任意对象。地图发送房主快照，不依赖各客户端独立随机模拟保持一致。

Godot 提供 RPC、连接、传输模式及实体 / 属性同步组件；权限和库存事务仍由业务层实现。参考：[高层联机 API](https://docs.godotengine.org/en/stable/tutorials/networking/high_level_multiplayer.html)、[MultiplayerSpawner](https://docs.godotengine.org/en/stable/classes/class_multiplayerspawner.html)、[MultiplayerSynchronizer](https://docs.godotengine.org/en/stable/classes/class_multiplayersynchronizer.html)。

## 6. 多人初始数值

出发时锁定人数 `P`（2–4），掉线 / 死亡 / 重连不降低本局难度，沿用单机地图尺寸、目标时间、个人身体和库存参数。下列值为本轮实施方案的首轮配置，可经试玩调整。

| 参数 | 多人配置 |
| --- | --- |
| 食物植物点 / 鱼存量 / 兔数量及上限 | 单机基数 × `1 + 0.5(P-1)`，向上取整 |
| 木 / 石 / 纤维 / 草药 / 落枝点 | 单机基数 × `1 + 0.25(P-1)`，向上取整 |
| 泉水 | 仍 3 个，出生可达性覆盖全体玩家 |
| 野猪 / 狼初始数量、上限与补充量 | 单机基数 × `1 + 0.25(P-1)`，向上取整，野猪不另乘猎物倍率 |
| 野猪 / 狼血量和攻击 | 单机基数 × `1 + 0.1(P-1)` |
| 存活者货币奖励 | 每人基础 600 + 自己探索 0–100 + 自己活动首次奖励 0–90 |
| 死亡者 | 无成功货币奖励，保留已获经验 / 点数 |

个人探索记录不因收到地图快照自动全开；经验与活动奖励归执行者。兔 / 危险动物按同一倍率放大对应补充量，鱼点存量上限也采用食物倍率，植物单点采集份数不放大。

成功返还本人随身 / 装备槽物资；公共箱、地面、设施不自动分配返仓；队友尸体取出的物品由当前持有者带回。断线但到期仍存活的角色有成功记录，个人重连 / 领取时应用一次。

## 7. 共享世界与个人档案

房主保存地图、时间、人数、名单、每人运行中身体 / 物资 / 技能进度、资源、建筑、动物、尸体、事务和结算；每人本地保存基地货币、仓库、永久技能、经验、点数。单机仍可一个完整档案事务。

稳定玩家 ID 和临时 peer ID 分离；重连恢复原角色。世界档 / 个人档有版本，连接检查玩法 / 内容配置兼容性。

跨端提交用任务 / 玩家 / 事件唯一 ID：房主先持久化提交记录，再发个人进度或结算收据；个人档记录已应用 ID，确认后房主记录已交付状态。提交记录包含权威提交时刻、相关状态差量和随机结果，异常恢复时重放已提交变化，不能只保留收据而让物资重新出现。重发重放同一结果，不重复发经验、钱或物资。

初始装备在个人档记录出发转移 / 占用状态，房主接收完成后开局；取消或投放失败按同一事务退回。断线不自动返仓，重连不再次复制装备。收据未到的个人进度保持待同步状态，由恢复流程核对，不能伪造已发结果。

本地档案与房主是好友合作的信任边界，第一版本不做中央账号、跨房间公共经济或平台级反作弊；业务仍校验身份、权限、数量与重复消息。

## 8. 阶段与验收

| 阶段 | 联机任务 | 验收 |
| --- | --- | --- |
| P0 | 会话、归属、命令 / 结果和模式策略 | UI 不直接写世界，单机通过本地会话 |
| P1–P3 | 库存权限 / 版本、多个角色、集中时钟 | 不写死全局唯一玩家，个人输入与世界分离 |
| P3.5 | 双人连接、快照、移动、并发拾取 / 建造、基础重连 | 同资源只得一份，同材料只扣一次，重连不复制角色 |
| P4–P6 | 身体 / 技能 / 动物 / 陷阱房主判定 | 客户端不独立决定伤害、产出、经验 |
| P6.5 | 2–4 人大厅、准备屏障、投票、死亡 / 尸体、赠送、存档 / 结算 | 只原队员重连，无复活，逐人结果只应用一次 |
| P7–P8 | 单机与合作整合，四人网络回归 | 无物资复制、重复奖励、模式混用和状态分叉 |

P3.5 已运行真实 ENet 双进程，并注入每向 50 ms 应用报文延迟和每 100 包丢 1 包，另验证一次库存请求丢失重试；这不是 OS 层 UDP 链路整形。P8 继续扩展到 150 ms / 5% 和四人会话，记录操作和恢复结果。

必验场景：抢同一物品、公共箱并发、同格建造、投饵后断线、死亡与到期同刻、个人菜单继续耗水、睡眠受袭、断线角色受伤 / 死亡、原成员重连、房主正常 / 异常退出、满仓返航、结算重发、旧任务加载不重置身体。
